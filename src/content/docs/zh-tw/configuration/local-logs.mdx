bilirec 預設把日誌寫到**標準錯誤**（終端或 Docker 日誌）。開啟本功能後，會在保留 stderr 的同時，把同一份日誌**異步寫入本地檔案**，並可按大小、天數自動輪轉。

也可與 [遠端日誌（VictoriaLogs）](/zh-tw/configuration/victorialogs/) 同時開啟。

## 快速開始

在 `.env` 中設定：

```bash
LOCAL_LOGS_ENABLED=true
LOCAL_LOGS_PATH=./logs/bilirec.log   # 可選，預設 <DATABASE_DIR>/bilirec.log
LOCAL_LOGS_FORMAT=pretty             # pretty 或 jsonline
```

重啟 bilirec。啟動日誌中會出現 `本地日誌已啟用：...`。

## 常用設定

| 變數 | 作用 | 預設 |
|------|------|------|
| `LOCAL_LOGS_ENABLED` | 是否寫入本地檔案 | `false` |
| `LOCAL_LOGS_PATH` | 檔案路徑；空則用 `<DATABASE_DIR>/bilirec.log` | (空) |
| `LOCAL_LOGS_FORMAT` | `pretty`（可讀文本）或 `jsonline` | `pretty` |
| `LOCAL_LOGS_MAX_SIZE_MB` | 單檔案超過該體積（MB）後輪轉 | `20` |
| `LOCAL_LOGS_MAX_AGE_DAYS` | 舊檔案保留天數 | `7` |
| `LOCAL_LOGS_MAX_BACKUPS` | 最多保留幾個舊檔案 | `3` |
| `LOCAL_LOGS_COMPRESS` | 輪轉後是否 gzip 壓縮舊檔案 | `false` |
| `LOCAL_LOGS_OVERFLOW` | 寫入排隊已滿時：`drop` 或 `block`，見下文 | `drop` |

批量大小、刷盤間隔、隊列深度等進階項見 [環境變數參考](/zh-tw/configuration/env-reference/)。

## 寫入跟不上時（`LOCAL_LOGS_OVERFLOW`）

日誌先進入記憶體排隊再批量寫盤。磁碟一時跟不上、排隊寫滿時：

### `drop`（預設）

丟掉這一條本地寫入，**不拖慢**正在打日誌的流程。適合與錄製同機：磁碟短暫變慢或日誌偏多時，優先保證錄製穩定。代價是本地檔案在高峰時可能少幾行；stderr 與已開啟的 VictoriaLogs 仍可能收到同一條。

### `block`

等隊列有空位再繼續。本地檔案更不容易缺行，但磁碟慢時，打日誌的流程可能卡住；若錄製相關路徑也在頻繁打日誌，可能感到錄製變頓。

<Aside type="caution">
與錄製同機時建議保持 `drop`。只有確實需要本地檔案儘量完整、且日誌盤 I/O 穩定時，再考慮 `block`，並儘量維持 Info 級別、必要時增大 `LOCAL_LOGS_BUFFER_SIZE`。
</Aside>

## 和其他輸出的關係

| 輸出 | 你會看到 | 排隊寫滿時 |
|------|----------|------------|
| stderr | 終端 / Docker 日誌裡的彩色文本 | 不受本項影響 |
| 本地檔案 | `pretty` 或 `jsonline` 檔案 | 由 `LOCAL_LOGS_OVERFLOW` 決定 |
| VictoriaLogs | 遠端 JSON 日誌 | 固定丟棄新行、不阻塞，見 [遠端日誌](/zh-tw/configuration/victorialogs/) |

關閉進程時會盡量把仍在排隊的本地日誌刷到磁碟。

## 故障排查

| 現象 | 可能原因 | 建議 |
|------|----------|------|
| 本地檔案缺行 | 排隊滿且策略為 `drop` | 屬預設取捨；要更完整可試 `block` 或減少日誌量 |
| 開了本地日誌後錄製偶發卡頓 | `block` + 磁碟慢 | 改回 `drop`，或改善日誌盤寫入 |
| 檔案未生成 | 未開啟，或路徑無寫權限 | 確認 `LOCAL_LOGS_ENABLED=true` 與目錄權限 |

bilirec 可在录制与转码流程中，向外部服务 POST **Webhook v2** 格式的 JSON。事件与字段约定见[Webhook v2 公开说明](https://rec.danmuji.org/reference/webhook/)。已按该格式对接的 **biliLive-tools** 或自建脚本（例如依赖 `FileClosed`）一般无需改解析逻辑。

## 启用

在 `.env` 中设置 `WEBHOOK_URLS`，**每行一个**完整 URL（与录播姬设置里换行填写多个地址的方式相同）。留空则不发送任何 webhook。

保存后**重启 bilirec**。Docker 镜像中对应环境变量同名，默认空。

## 对接 biliLive-tools

[biliLive-tools](https://github.com/renmu123/biliLive-tools) 在 webhook 设置里选择「录播姬」，地址形如：

`http://你的主机:端口/webhook/bililiverecorder`

把该地址写入 bilirec 的 `WEBHOOK_URLS`（可多行添加多个工具）。

在 biliLive-tools 里：

1. 开启 webhook，类型选「录播姬」，地址填上文的 URL。
2. 把**录播目录**（`recoderFolder`）设成与 bilirec 的 **`OUTPUT_DIR` 完全一致**（本机部署务必填写；用 Docker 时请与 bilirec 使用同一磁盘挂载路径）。
3. 若要用工具压制弹幕或自动上传，除下文弹幕格式外，请确认 bilirec 的成片路径就在该录播目录下（与平时录制保存位置相同）。
4. **不要**在 bilirec 开启 `CONVERT_TO_MP4` 指望工具「只上传已转好的 MP4」。biliLive-tools 在收到成对的 `FileOpening` / `FileClosed` 后，会按 Webhook 配置对 **录制落盘的原始流文件**做转封装（`convert2Mp4` → 内部 `processConversion`），再进入压制、上传等步骤；这与 bilirec 本地转码后发事件的时序不一致。工具源码：[WebhookHandler.processConversion](https://github.com/renmu123/biliLive-tools/blob/master/packages/http/src/services/webhook/webhook.ts)；内置录制器与 Webhook 转封装的说明见 [recorder 文案 `convert2Mp4`](https://github.com/renmu123/biliLive-tools/blob/master/packages/app/src/renderer/src/enums/recorder.ts)。
5. 在 biliLive-tools 的 Webhook **全局或房间**设置里开启 **转封装为 MP4**（`convert2Mp4`），并按需配置压制预设、上传账号等。挂机上传场景完整清单见 [全自动挂机上传](/zh-cn/guides/auto-upload/)。

<Aside type="note">
若要用 biliLive-tools 压制弹幕或上传，请把 `DANMAKU_OUTPUT_FORMAT` 设为 **xml**，以便生成与视频同名的 `.xml` sidecar。默认 **jsonl** 适合 bilirec-web 回放，外部压制工具通常只认 xml。详见 [弹幕 XML 的后续使用](/zh-cn/guides/danmaku-xml/)。
</Aside>

<Aside type="caution">
对接 biliLive-tools 时，bilirec 侧请保持 **`CONVERT_TO_MP4=false`**（默认）。本地转码留给 [自用录像库](/zh-cn/guides/personal-archive/) 或 bilirec-web 回放等场景即可。
</Aside>

## 会发送哪些事件

与[录播姬 Webhook 说明](https://rec.danmuji.org/reference/webhook/)一致，包括：

- `StreamStarted` / `StreamEnded`：已订阅房间开播、下播（未开录制也会发）
- `SessionStarted` / `SessionEnded`：一次录制任务的开始与结束（结束与停止录制同时发出，可能早于最后一个 `FileClosed`）
- `FileOpening` / `FileClosed`：每个分段文件打开与写完（对接 biliLive-tools 时主要依赖这一对，且应对 **原始录制文件**成对出现）

**bilirec 本地转码（`CONVERT_TO_MP4`）与 Webhook 时序：**

- **默认（`CONVERT_TO_MP4=false`）**：分段写完后立即对 **flv/ts/fmp4 等录制路径**发送 `FileClosed`。这是对接 biliLive-tools 时应使用的模式。
- **开启 `CONVERT_TO_MP4` 时**：写盘完成后**不会**立刻对原始流发 `FileClosed`，而是入队转码；转码成功后会对 **mp4/m4a 输出**再发送一对 `FileOpening` 与 `FileClosed`（原始流上的打开事件仍对应录制阶段）。适合只消费最终 MP4 的自建脚本，或 [自用录像库](/zh-cn/guides/personal-archive/) 等不经过 biliLive-tools Webhook 管线的场景。转码失败会重试，单次失败不会对成品误发 `FileClosed`。

失败或非 2xx 时最多重试 3 次，同一事件的 `EventId` 不变，便于接收方去重。

## 路径与文件名

bilirec 的目录结构为 `{主播名}-{房间号}/文件名`，与录播姬默认模板不同，只要 **`OUTPUT_DIR` 与工具里配置的录播根目录一致**即可，不必改 bilirec 的文件名规则。

完整参数说明见 [环境变量参考](/zh-cn/configuration/env-reference/) 中的 `WEBHOOK_URLS`。

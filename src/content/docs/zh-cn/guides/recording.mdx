## 手动录制

在 Web 界面中输入直播间房间号，在确认页选择画质、允许的流格式、是否仅录制音频、是否录制弹幕与时长，点击开始录制。

<Aside type="note">
Web 界面中「画质」为请求偏好，不可用时会尽量选用该直播支持的较高档位。「流格式」可多选，作为严格允许清单：未选表示允许全部格式；选中后只会在所选格式内尝试。「仅录制音频」对应 API 参数 `only_audio=true`，「录制弹幕」对应 `record_danmaku=true`。不传 `qn` 时后端默认使用原画（`10000`）。
</Aside>

也可通过 API 启动（推荐 JSON body；仍支持 query，详见 [录制 API](/zh-cn/api/record/)）：

```bash
curl -X POST "http://127.0.0.1:8080/record/12345/start" \
  -H "Content-Type: application/json" \
  -d '{"duration_minutes":30,"stream_profiles":["http-flv"],"qn":150,"record_danmaku":true}'
```

### 画质码（qn）

| 值 | 画质 |
|----|------|
| `80` | 流畅 |
| `150` | 高清 |
| `250` | 超清 |
| `400` | 蓝光 |
| `10000` | 原画 |
| `20000` | 4K |
| `30000` | 杜比 |

### 仅录制音频（only_audio）

| 值 | 说明 |
|----|------|
| 不传 / `false` | 录制音视频 |
| `true` | 仅录制音频 |

### 录制弹幕（record_danmaku）

开启后，bilirec 会同时保存普通弹幕、醒目留言、礼物和舰长等互动记录。记录会保存为与视频同名的弹幕文件；视频分段或断流恢复后，新的视频文件会对应新的弹幕文件。

Web 回放要显示弹幕滚动和礼物特效，建议使用默认的 `jsonl` 格式。输出格式、消息高峰处理和磁盘写入相关调节见[弹幕录制配置](/zh-cn/configuration/danmaku/)。

### 流格式（stream_profile / stream_profiles）

严格允许清单。

- **开始录制 API**：JSON body 字段 `stream_profiles`（字符串数组）；query 仍可用 `stream_profile`（逗号分隔）。
- **房间配置 API**：JSON 字段 `stream_profiles`，为字符串数组。

| 值 | 说明 |
|----|------|
| 不传 / 空 | 允许全部格式；同画质下按 HTTP-FLV → HLS-fMP4 → HLS-TS 排序尝试 |
| `http-flv` | 仅 HTTP-FLV（PK/分辨率切换时自动分段） |
| `hls-ts` | 仅 HLS-TS（不执行文件轮转） |
| `hls-fmp4` | 仅 HLS-fMP4（默认将 init 与媒体分片写入同一文件；仅 init 内容变更时分段） |

多选时只会在所选格式内尝试；同画质下仍按 FLV → fMP4 → TS 排序。想尽量录到下播结尾时可选 HLS；要更贴近直播边缘时可选 FLV。

### 录制时长（duration_minutes）

| 值 | 说明 |
|----|------|
| 不传 / `0` | 使用系统预设（`MAX_RECORDING_HOURS`） |
| `-1` | 无限录制 |
| 正整数 | N 分钟后自动停止 |

## 订阅房间

订阅直播间后，可配置开播自动录制与开播通知：

1. 在 Web 界面添加房间订阅
2. 配置自动录制与通知选项

![桌面端订阅管理](/images/web-ui/desktop-sub-config.png)

</TabItem>
<TabItem label="移动端">

![移动端订阅管理](/images/web-ui/mobile-sub-config.png)

</TabItem>
</Tabs>

通过 API：

```bash
# 订阅房间
curl -X POST http://127.0.0.1:8080/room/12345

# 配置自动录制（可同时设置画质与允许的流格式）
curl -X PUT http://127.0.0.1:8080/room/12345/config \
  -H "Content-Type: application/json" \
  -d '{"auto_record":true,"notify":true,"record_duration_minutes":120,"qn":150,"record_danmaku":true,"stream_profiles":["hls-fmp4","hls-ts"]}'
```

为房间开启 **开播通知** 或 **自动录制** 后，后台会定期检查该房间的直播状态。服务启动时先检查所有相关房间一次，之后将房间分成若干组、分组轮流检查，避免订阅较多时 CPU 瞬间飙高。检测到新一场直播时：若开启了通知则推送消息；若开启了自动录制则按该房间 config 中的**全部开录相关项**自动开始录制。分组与检查周期默认随订阅规模自动调整，详见 [录制配置](/zh-cn/configuration/recording/#订阅房间状态检查)。

## 自动录制

启用 `auto_record: true` 后，检测到开播时会用该房间配置里与开录相关的字段一次性开录，与手动 `POST /record/:roomID/start` 的 JSON body / query 字段同义，包括：

- `record_duration_minutes`（时长上限：`0` 系统预设，`-1` 不限时，正整数为 N 分钟）
- `qn`、`stream_profiles`、`only_audio`、`record_danmaku`、`delete_oldest_on_low_disk`

其中 `stream_profiles` 为空或省略表示允许全部流格式；为数组时为严格允许清单，元素为 `http-flv`、`hls-ts`、`hls-fmp4`。

<Aside type="note">
`record_duration_minutes` 只作用于自动录制。手动开录请在 `POST /record/:roomID/start` 的 JSON body 或 query 中传入 `duration_minutes`（未传则按系统预设）；其它开录选项也可在该次请求中单独指定。
</Aside>

## 停止录制

```bash
curl -X POST http://127.0.0.1:8080/record/12345/stop
```

完整 API 参考见 [录制管理 API](/zh-cn/api/record/)。

<Aside type="tip">
**常见问题：** 直播中断后出现多个文件是正常分段；CPU 飙高可能与订阅检查有关。详见 [常见问题](/zh-cn/guides/faq/#后端录制) 与 [性能与容量规划](/zh-cn/guides/faq/#性能与容量规划)。
</Aside>

## 开始录制

```http
POST /record/:roomID/start
Content-Type: application/json

{
  "duration_minutes": 30,
  "qn": 150,
  "only_audio": false,
  "record_danmaku": true,
  "stream_profiles": ["http-flv", "hls-ts"],
  "delete_oldest_on_low_disk": false
}
```

也可通过 query 传参（与 JSON 字段同名，使用 snake_case）。**二者互斥**：服务端以是否声明请求体为准（无 body 时只读 query）；一旦带有 body（含空 JSON 对象 `{}`），则只走 JSON、忽略 query。query 模式请勿附带 body（例如 axios 使用 `undefined` 而非 `null`，避免发送字面量 `null`）。未在 JSON 中出现的字段按默认值处理（与 query 模式下「不传」一致）。官方 Web 通过 query 传参且不附带请求体。

### duration_minutes

| 值 | 说明 |
| -- | ---- |
| 不传 / `0` | 使用系统预设（`MAX_RECORDING_HOURS`） |
| `-1` | 无限录制 |
| 正整数 | N 分钟后自动停止 |

### stream_profile / stream_profiles

允许的流格式清单（严格限制）。

- **JSON body**：`stream_profiles` 字符串数组（推荐，与房间配置一致）。
- **query**：`stream_profile`，单个值或英文逗号分隔（如 `hls-fmp4,hls-ts`）。
- body 中若同时提供 `stream_profiles` 与 `stream_profile`，以 `stream_profiles` 为准。

| 值 | 说明 |
| -- | ---- |
| 不传 / 空 | 允许全部格式；同画质下按 HTTP-FLV → HLS-fMP4 → HLS-TS 排序尝试 |
| `http-flv` | 仅 HTTP-FLV |
| `hls-ts` | 仅 HLS-TS |
| `hls-fmp4` | 仅 HLS-fMP4 |
| `hls-fmp4,hls-ts` | 仅允许所列格式（示例） |

多选时只会在所选格式内尝试；同画质下仍按 FLV → fMP4 → TS 排序。

### qn（画质码）

优先画质（请求偏好，不保证与所选完全一致）。

| 值 | 画质 |
| -- | ---- |
| 不传 | 原画（`10000`） |
| `80` | 流畅 |
| `150` | 高清 |
| `250` | 超清 |
| `400` | 蓝光 |
| `10000` | 原画 |
| `20000` | 4K |
| `30000` | 杜比 |

### only_audio

| 值 | 说明 |
| -- | ---- |
| 不传 / `false` | 录制音视频 |
| `true` | 仅录制音频 |

### record_danmaku

是否同时保存弹幕、醒目留言、礼物和舰长等互动记录。

| 值 | 说明 |
| -- | ---- |
| 不传 / `false` | 不录制互动记录 |
| `true` | 录制互动记录，并在视频旁保存同名弹幕文件 |

弹幕文件格式与写入行为由 [弹幕录制配置](/zh-cn/configuration/danmaku/)控制。使用 Web 播放器显示弹幕滚动和礼物特效时，建议使用默认的 `jsonl` 格式。

### delete_oldest_on_low_disk

可用空间低于 `MIN_DISK_SPACE_BYTES` 时，是否先删除该房间目录里文件名时间戳最早的录像（含同名弹幕附件），再重新检查空间并尝试启动。

| 值 | 说明 |
| -- | ---- |
| 不传 / `false` | 空间不足时直接拒绝启动（HTTP `507`） |
| `true` | 按文件名中的 `YYYYMMDD_HHMMSS` 与分段号删除该房间最旧媒体文件，删完仍不足则拒绝启动 |

断线恢复沿用本次启动时的选项。新旧只看文件名，不看文件修改时间；对不上时间戳的文件不会删；其他房间的文件不会删。

**注意：**

- 录 4K / 杜比建议显式传 `qn`（如 `qn=20000`、`qn=30000`）
- `qn ≥ 20000` 时自动启用 `*_HIGH` 高画质内存池，一般无需改环境变量
- 若遇卡顿或内存不足，参见 [高码率 / 4K 调参](/zh-cn/configuration/high-bitrate-tuning/) 与 [内存占用估算](/zh-cn/configuration/memory-estimation/)

```bash
curl -X POST "http://127.0.0.1:8080/record/12345/start" \
  -H "Content-Type: application/json" \
  -d '{"duration_minutes":30,"stream_profiles":["http-flv"],"qn":150,"only_audio":true,"record_danmaku":true,"delete_oldest_on_low_disk":true}'
```

仍可使用 query（例如脚本或旧版客户端）：

```bash
curl -X POST "http://127.0.0.1:8080/record/12345/start?duration_minutes=30&stream_profile=http-flv&qn=150&only_audio=true&record_danmaku=true&delete_oldest_on_low_disk=true"
```

### 错误响应

| HTTP | 说明 |
| ---- | ---- |
| `400` | 无效参数、房间未开播、已在录制、正在恢复流等 |
| `404` | 房间不存在 |
| `409` | 该房间录制正在启动中（并发请求冲突） |
| `410` | 无法连接到任何可用流 URL |
| `429` | 已达到 `MAX_CONCURRENT_RECORDINGS` 上限 |
| `507` | 磁盘可用空间低于 `MIN_DISK_SPACE_BYTES` |

常见 `400` 消息：`该房间已在录制中`、`该房间正在恢复流`、`房间并非直播状态`、`无可用的视频流 URL`。

## 停止录制

```http
POST /record/:roomID/stop
```

## 批量获取状态

```http
POST /record/statuses
Content-Type: application/json

{ "roomIDs": [123, 456, 789] }
```

也支持 query：`?roomIDs=123,456,789`

```json
{ "123": "recording", "456": "idle", "789": "recovering" }
```

状态值：`idle`（未录制）、`recording`（录制中）、`recovering`（流中断，正在重连恢复）。

## 批量获取统计

```http
POST /record/stats
Content-Type: application/json

{ "roomIDs": [123, 456, 789] }
```

```json
{
  "123": {
    "bytes_read": 1100000,
    "bytes_written": 1048576,
    "danmaku_bytes_written": 4096,
    "record_danmaku": true,
    "status": "recording",
    "start_time": 1234567890,
    "elapsed_seconds": 120,
    "output_path": "records/tester-123/live-title.flv",
    "actual_qn": 150,
    "actual_stream_format": "http-flv",
    "is_audio_only": false,
    "room_title": "开录时的直播标题"
  }
}
```

`bytes_read` 为从直播流读入的字节累计（尚未写入磁盘）。`bytes_written` 为实际写入录制文件的字节累计（含切档），通常略小于或接近最终文件大小。`danmaku_bytes_written` 为弹幕文件实际写入磁盘的字节累计，按已落盘的数据计数，而不是仅进入等待队列时计数。

`room_title` 为**开始录制时**固定的房间标题（用于输出文件名），与房间信息接口返回的当前标题可能不同。

bilirec 默认把日志写到**标准错误**（终端或 Docker 日志）。开启本功能后，会在保留 stderr 的同时，把同一份日志**异步写入本地文件**，并可按大小、天数自动轮转。

也可与 [远程日志（VictoriaLogs）](/zh-cn/configuration/victorialogs/) 同时开启。

## 快速开始

在 `.env` 中设置：

```bash
LOCAL_LOGS_ENABLED=true
LOCAL_LOGS_PATH=./logs/bilirec.log   # 可选，默认 <DATABASE_DIR>/bilirec.log
LOCAL_LOGS_FORMAT=pretty             # pretty 或 jsonline
```

重启 bilirec。启动日志中会出现 `本地日志已启用：...`。

## 常用设置

| 变量 | 作用 | 默认 |
|------|------|------|
| `LOCAL_LOGS_ENABLED` | 是否写入本地文件 | `false` |
| `LOCAL_LOGS_PATH` | 文件路径；空则用 `<DATABASE_DIR>/bilirec.log` | (空) |
| `LOCAL_LOGS_FORMAT` | `pretty`（可读文本）或 `jsonline` | `pretty` |
| `LOCAL_LOGS_MAX_SIZE_MB` | 单文件超过该体积（MB）后轮转 | `20` |
| `LOCAL_LOGS_MAX_AGE_DAYS` | 旧文件保留天数 | `7` |
| `LOCAL_LOGS_MAX_BACKUPS` | 最多保留几个旧文件 | `3` |
| `LOCAL_LOGS_COMPRESS` | 轮转后是否 gzip 压缩旧文件 | `false` |
| `LOCAL_LOGS_OVERFLOW` | 写入排队已满时：`drop` 或 `block`，见下文 | `drop` |

批量大小、刷盘间隔、队列深度等进阶项见 [环境变量参考](/zh-cn/configuration/env-reference/)。

## 写入跟不上时（`LOCAL_LOGS_OVERFLOW`）

日志先进入内存排队再批量写盘。磁盘一时跟不上、排队写满时：

### `drop`（默认）

丢掉这一条本地写入，**不拖慢**正在打日志的流程。适合与录制同机：磁盘短暂变慢或日志偏多时，优先保证录制稳定。代价是本地文件在高峰时可能少几行；stderr 与已开启的 VictoriaLogs 仍可能收到同一条。

### `block`

等队列有空位再继续。本地文件更不容易缺行，但磁盘慢时，打日志的流程可能卡住；若录制相关路径也在频繁打日志，可能感到录制变顿。

<Aside type="caution">
与录制同机时建议保持 `drop`。只有确实需要本地文件尽量完整、且日志盘 I/O 稳定时，再考虑 `block`，并尽量维持 Info 级别、必要时增大 `LOCAL_LOGS_BUFFER_SIZE`。
</Aside>

## 和其他输出的关系

| 输出 | 你会看到 | 排队写满时 |
|------|----------|------------|
| stderr | 终端 / Docker 日志里的彩色文本 | 不受本项影响 |
| 本地文件 | `pretty` 或 `jsonline` 文件 | 由 `LOCAL_LOGS_OVERFLOW` 决定 |
| VictoriaLogs | 远程 JSON 日志 | 固定丢弃新行、不阻塞，见 [远程日志](/zh-cn/configuration/victorialogs/) |

关闭进程时会尽量把仍在排队的本地日志刷到磁盘。

## 故障排查

| 现象 | 可能原因 | 建议 |
|------|----------|------|
| 本地文件缺行 | 排队满且策略为 `drop` | 属默认取舍；要更完整可试 `block` 或减少日志量 |
| 开了本地日志后录制偶发卡顿 | `block` + 磁盘慢 | 改回 `drop`，或改善日志盘写入 |
| 文件未生成 | 未开启，或路径无写权限 | 确认 `LOCAL_LOGS_ENABLED=true` 与目录权限 |

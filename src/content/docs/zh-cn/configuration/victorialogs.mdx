bilirec 默认把日志写到**标准错误**（终端或 Docker 日志），格式为人类可读的彩色文本。**默认不向任何远程系统发送日志**。

开启本功能后，会在保留本地可读日志的同时，把同一份日志以 **JSON Line** 格式异步推送到 [VictoriaLogs](https://docs.victoriametrics.com/victorialogs/)。适合在 NAS / 树莓派上长期录制时，用 Grafana 或 VMUI 按房间、模块、级别检索历史日志。

## 前置知识

- [VictoriaLogs 快速开始](https://docs.victoriametrics.com/victorialogs/quickstart/) — 安装与 `/insert/jsonline` 写入
- [VictoriaLogs 查询](https://docs.victoriametrics.com/victorialogs/querying/) — LogsQL 与 VMUI
- 若已使用 [监控指标](/zh-cn/configuration/metrics/) 的 VictoriaMetrics，可在同一台机器上再部署 VictoriaLogs（默认端口常为 `9428`）

bilirec **只负责推送**；存储、保留策略与可视化由 VictoriaLogs / Grafana 完成。

## 快速开始

1. 安装并启动 VictoriaLogs（确保可从 bilirec 所在主机访问其 HTTP 端口）
2. 在 `.env` 中设置：

```bash
export VICTORIALOGS_ENABLED=true
export VICTORIALOGS_URL=http://127.0.0.1:9428
```

3. 重启 bilirec。启动日志中会出现 `VictoriaLogs 远程日志已启用：...`
4. 在 VictoriaLogs VMUI 或 Grafana（VictoriaLogs / Loki 兼容数据源）中查询，例如：

```text
app:bilirec AND logger:recorder
```

<Aside type="caution">
远程推送失败**不会**阻止录制或 API 服务；失败的批次会被丢弃，并在标准错误打印简短提示。请勿把 VictoriaLogs 当作唯一日志留存手段，本地/Docker 日志仍应保留。
</Aside>

## 环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `VICTORIALOGS_ENABLED` | 是否启用远程日志推送 | `false` |
| `VICTORIALOGS_URL` | VictoriaLogs 根地址（**不含**路径，程序自动拼接 `/insert/jsonline`） | (空) |
| `VICTORIALOGS_STREAM_FIELDS` | 日志流字段（逗号分隔，低基数） | `app,logger` |
| `VICTORIALOGS_ACCOUNT_ID` | 多租户 AccountID（HTTP 头，可选） | (空) |
| `VICTORIALOGS_PROJECT_ID` | 多租户 ProjectID（HTTP 头，可选） | (空) |
| `VICTORIALOGS_TIMEOUT` | 单次 HTTP 推送超时，如 `10s` | `10s` |

完整列表见 [环境变量参考](/zh-cn/configuration/env-reference/)。

启用条件：`VICTORIALOGS_ENABLED=true` **且** `VICTORIALOGS_URL` 非空。若只开了开关却未填 URL，程序会打一条警告并跳过远程日志，**不会**因此退出。

## 日志字段说明

每条远程日志为 JSON 一行，主要字段：

| 字段 | 含义 |
|------|------|
| `_time` | ISO8601 时间戳 |
| `_msg` | 日志正文 |
| `level` | 级别（`debug` / `info` / `warn` / `error` 等） |
| `logger` | 模块名（与代码中 `logger.Named("...")` 一致，如 `recorder`、`danmaku`） |
| `app` | 固定为 `bilirec` |
| `instance` | 主机名（便于区分多台设备） |
| 其它 | 结构化字段（如 `room`、`file`、`processor`、`task_id`、`error`） |

`app` 与 `logger` 用作 **stream fields**（日志流分组），便于在 VictoriaLogs 中按应用与模块过滤。**请勿**把 `room_id` 等高基数字段加入 `VICTORIALOGS_STREAM_FIELDS`，否则会产生过多日志流、影响查询性能。

## 与本地日志文件的关系

- **标准错误**：始终为人类可读彩色文本（Docker / 终端日志）
- **本地文件**（可选，`LOCAL_LOGS_ENABLED=true`）：异步写入磁盘，格式可选 `pretty` / `jsonline`；队列满时默认 **丢弃新行、不阻塞**，详见 [本地日志文件](/zh-cn/configuration/local-logs/)
- **远程**：JSON Line，异步批量推送（约 1 秒或 64 KiB 一批）
- 远程缓冲区满时**丢弃**新日志行，不阻塞录制线程
- 进程退出时（含 `fx` 优雅停止）会尽量 flush 剩余批次

## Grafana 接入简述

1. 在 Grafana 安装 [VictoriaLogs datasource plugin](https://grafana.com/grafana/plugins/victoriametrics-logs-datasource/)，并添加 `VictoriaLogs` 数据源。
2. 在 Explore 用 LogsQL 查询 `app:bilirec`，再按 `logger`、`level`、`room` 缩小范围。
3. 需要现成视图时，导入 [bilirec 日志分析仪表盘](/dashboards/zh-cn/bilirec-logging.json) 或 [bilirec 原始日志浏览仪表盘](/dashboards/zh-cn/bilirec-logs-explorer.json)。

日志分析盘看数量趋势与传输健康，原始日志浏览盘看完整内容与专题日志。若要看丢弃、失败、重试、发送队列，还需开启 [监控指标](/zh-cn/configuration/metrics/) 并选择 Prometheus/VictoriaMetrics 指标数据源。

指标类面板见 [Grafana 仪表盘](/zh-cn/configuration/grafana-dashboards/)。

## 故障排查

| 现象 | 可能原因 | 建议 |
|------|----------|------|
| 启动无「远程日志已启用」 | 未设 `VICTORIALOGS_ENABLED=true` 或 URL 为空 | 检查 `.env` 并重启 |
| 标准错误出现 `victorialogs post` | VictoriaLogs 未启动、地址错误或网络不通 | 确认 URL、防火墙与容器网络 |
| 标准错误出现 `buffer full, dropped` | 日志量过大或 VictoriaLogs 响应慢 | 提高 VictoriaLogs 资源、减少 `DEBUG`、或接受丢弃 |
| VMUI 查不到日志 | 查询条件过严、时间范围不对 | 先试 `app:bilirec`，扩大时间范围 |

## 与监控指标的配合

[监控指标](/zh-cn/configuration/metrics/)（`METRICS_ENABLED`）与远程日志**相互独立**，可只开其一，也可同时开启：指标走 Prometheus 抓取，日志走 VictoriaLogs 推送，在 Grafana 中分别配置数据源即可。日志分析仪表盘会使用 `bilirec_victorialogs_logs_dropped_total`、`bilirec_victorialogs_requests_failed_total`、`bilirec_victorialogs_retries_total` 与 `bilirec_victorialogs_queue_bytes`，以时间序列显示远程日志传输健康。
